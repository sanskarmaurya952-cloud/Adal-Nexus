# Milestone 5.1 quality audit (2026-10-28)

**Method.** The records from the second live run of Milestone 5 (saved as `m5-run2-original-records.json`) were audited by
(1) re-visiting every recorded page with the app's own `browser.open` and URL guard and checking that each stored evidence
quote still appears on the live page, and (2) reading each stored quote and value and judging whether the page text supports
the claim. This is a judgment from quotes, name/title and meta text; **I did not read every page in full**, and
the classification is mine, not a human reviewer's. "Visited successfully" and "claim verified" are separate: all 10 sites
loaded (HTTP 200), but a loaded page does not verify a claim.

**What could not be recovered.** The first M5 live run was not persisted (outputs lived only in server memory) and cannot be
audited. The second run was recovered from a copy saved by my helper script. From now on the server saves finished runs to
`data/runs/<runId>.json` (git-ignored).

**Re-visit result.** 10/10 sites reachable, no CAPTCHA or bot wall encountered. Evidence quotes present live: all of them for 8
sites; **Jasper**: the home-page target-market quote was no longer present (page changed); **Synthesia**: 0 of 12 pricing
quotes present (the page shows localized prices, so the earlier values are not reproducible). Both are therefore *not
independently verified*.

Classification key: **V** verified, **X** incorrect, **A** ambiguous, **U** unavailable (no evidence found on visited pages).

## Remaining weaknesses seen in the audit
- Target-market extraction remains pattern-based; "sales teams"/"companies" style hits can be use cases rather than audiences.
- Per-seat labelling is inconsistent when a page shows it for only one of two prices (Jasper).
- Localized/geo-priced pages (Synthesia) are not reproducible between visits.
- Pricing "found" can be partial (only some plans); the reason field says how many were excluded.
