# AdaL Nexus

AI-native browser workspace (hackathon MVP). Goal: a natural-language task becomes a plan, is executed with a real
Playwright-controlled browser, produces a real `.xlsx`, and is independently verified.

## Setup

Requires Node 20.6+ (developed on Node 24).

```
npm install
npm run dev                 # server :3001 + web :5173, open http://localhost:5173
```

The app starts and works **without** an API key and **without** a browser installed. Only plan generation needs a key,
and only the browser tools need a browser.

### Browser setup (required for browser.search / open / extract)

Browser tools drive a **visible** Chromium-family window using `playwright-core`. Pick one:

- **Use your installed Chrome (no download):** put `BROWSER_CHANNEL=chrome` in `.env` (or `msedge` for Edge).
- **Use Playwright's Chromium (about 150 MB download, once):** `npx playwright-core install chromium`, leave
  `BROWSER_CHANNEL` empty.

The window opens on the first browser step and uses a fresh temporary profile (no cookies or logins from your own
browser). If the browser is missing, the step fails with a message that says which of the above to do.

### Enable plan generation (Gemini)

1. Create a key in Google AI Studio: https://aistudio.google.com/apikey (free tier, no billing required).
2. `copy .env.example .env`, then edit `.env` locally (git-ignored). **Never put a key in `.env.example`, docs, tests
   or chat.**
   ```
   GEMINI_API_KEY=<your key>
   GEMINI_MODEL=gemini-2.5-flash-lite
   ```
3. Restart. The header badge reads `LLM: gemini (model)`.
4. `npm run llm:check` shows configuration without any API call (never prints the key); `npm run llm:check -- --live`
   sends ONE tiny request.

`GEMINI_MODEL` is configurable. The official pricing page (checked 2026-10-27) listed `gemini-2.5-flash-lite` and
`gemini-3.8-flash` with a free tier; limits change, free quota is limited, and free-tier content may be used by Google
to improve its products. Verify at https://ai.google.dev/gemini-api/docs/pricing.

Other commands: `npm test`, `npm run typecheck`, `npm run build`, `npm start` (server only).
If `npm run dev` fails with `EADDRINUSE`, a previous server is still running on 3001/5173.

## Browser research tools (M4)

All three are read-only and go through the existing planner, policy engine, approval gates, cancellation and SSE event
stream like any other tool. They are not "sensitive", so they do not ask for approval.

| Tool | Input | What it does |
|------|-------|--------------|
| `browser.search` | `{"query": string, "maxResults"?: 1-20}` | Loads `https://html.duckduckgo.com/html/?q=...` in the visible browser and returns title / URL / snippet for each result, with the search page as source. Fails honestly on a CAPTCHA or bot wall (never bypassed). Zero parsed results is reported `unverified`, not `completed`. |
| `browser.open` | `{"url": string}` | Opens one public http(s) URL. Returns final URL (after redirects), HTTP status and title. HTTP 4xx/5xx, DNS/connection/TLS/timeout failures and CAPTCHA/bot walls are **step failures** with the real reason. |
| `browser.extract` | `{"fields"?: ["pricing","description","links"], "keywords"?: string[]}` | Reads the page that `browser.open` just opened. Returns `sourceUrl` plus evidence-backed facts (below). Never launches a browser itself. |

**Evidence and "Unavailable".** Extraction is deterministic (fixed patterns, no LLM). Pricing is reported only when a
price such as `$49 per user per month` appears in the page's visible text with pricing context; every price carries a
quoted snippet (an exact substring of the page text) and the source URL. Otherwise `pricing.summary` is
`"Unavailable"` (or `"Unavailable (contact sales)"`, or a free-tier-only note). Funding figures such as `$25M` are not
treated as prices. After extracting, the tool re-reads the page and confirms every quote is still there; if not, the step
ends `unverified`, never `completed`.

**Page content is untrusted.** Page text is never sent to the LLM in M4 and never used to choose tools, URLs to visit or
approvals. It is only matched against fixed patterns and echoed back as quoted data (control characters stripped,
lengths capped). The UI shows tool output as plain text.

**URL safety** (`browser/urlSafety.ts`), applied to the requested URL, every redirect, and every sub-resource request
(via a Playwright request hook), plus the final URL and the page being read:
- only `http:` / `https:` for navigation (`file:`, `javascript:`, `data:`, `chrome:`, `ftp:` etc. blocked);
- no embedded credentials; navigation ports limited to 80, 443, 8080, 8443;
- blocks `localhost`, `*.localhost`, `*.local`, `*.internal`, `*.lan`, `*.home.arpa`, single-label host names;
- blocks private / loopback / link-local / CGNAT / reserved IPv4 and IPv6 (including IPv4-mapped IPv6, NAT64, 6to4) and
  decimal / hex / octal IPv4 spellings;
- DNS check: a public-looking name that resolves to a private address is refused.

**Manual takeover.** The window is a normal visible browser. Click **Pause** (the run pauses before the next step),
then use the window yourself; **Resume** continues from whatever page is open. `browser.extract` refuses to read a page
the URL policy forbids, even if you navigated there. **Cancel** aborts a navigation in progress.

## Step references and the research workflow (M5)

**Passing data between steps.** Any step input may contain `{"$ref": "stepId.path.to.value"}` (a JSON object with only
that key; path segments are `[A-Za-z0-9_-]`, array indexes are numbers, `__proto__`/`constructor`/`prototype` are forbidden).
- *Plan time* (controller and planner): the syntax must be valid and the step must be **earlier** in the plan (no unknown,
  self or forward references); otherwise the plan is rejected before anything runs.
- *Run time* (controller): the value is read from the output of a `completed` or `unverified` step only. A missing step
  output or path **fails the step** (later steps are `skipped`); it is never silently ignored. The resolved value is a deep
  clone, capped at 500,000 characters, and only handed to the tool, which still validates its own input. Policy and approval
  decisions depend on tool names, so a reference cannot change them. Snapshots keep the unresolved reference.
- Stored event history omits step outputs (they can be large); the live event stream and `GET /api/run` snapshot have them.

**Research tools** (registered explicitly; read-only; they only compose `browser.search` / `browser.open` and pure analysis,
so every URL passes the URL-safety rules):

| Tool | Input | Result |
|------|-------|--------|
| `research.find_sources` | `{"query", "maxSources"?: 1-15}` | Runs `browser.search`, keeps one site root per result that is not a news/directory/social domain and whose title/snippet is not a list/ranking. If search fails, is blocked (CAPTCHA), returns nothing, or yields too few, tops up from the **curated fallback seed list** (`research/seeds.ts`). Every source has `origin: "search"` or `"fallback"` and fallback sources carry the label; the step note and `fallbackReason` say why. |
| `research.collect` | `{"sources": [...] (normally a $ref), "maxStartups"?: 1-15}` | Validates `sources` at runtime, opens each site (CAPTCHA/HTTP/DNS failures become `failed` records and the next candidate is used), follows one same-site pricing link when the home page has no clear price, and builds a record: name, product, target market, pricing. `unverified` if fewer than requested were researched; fails if none. |
| `research.consolidate` | `{"records": [...] (normally a $ref), "expectedCount"?: 1-50}` | Re-validates every record against the runtime schema, dedupes by site, reports counts (fallback, Unavailable per field, ambiguous pricing). `failed` if any record breaks the schema, `unverified` if fewer than expected. |

**Evidence rules.** Every fact is `{value, evidence: [{kind, quote, sourceUrl}]}`. A value other than "Unavailable" must
have evidence (the schema check rejects it otherwise). Name = the domain's brand word, only if it appears in the page title;
product = meta description (or a visible heading); target market = audience phrases such as "built for developers" with
quotes; pricing = quoted price strings. **Ambiguous pricing is "Unavailable"**: promotional wording near prices (e.g.
"first month 83% off"), prices in more than one currency, or more than 6 different price points; the raw prices and quotes
are kept under `pricing.prices` / `pricing.evidence` with a `reason`. Contact-sales and free-tier-only pages are
"Unavailable (...)". Page text is untrusted data and is never sent to an LLM or used to choose URLs outside the same site.

The seed list is a human-curated set of company homepages, **not evidence**; each is visited live and only facts found on the
page are recorded.

## How planning works (M3)

1. **Generate plan** sends the task and the list of *registered* tools to Gemini, requesting JSON that matches a schema.
2. The reply is untrusted: only whitelisted fields are copied (`goal`, `limitations`, and per step `id`, `title`, `tool`,
   `inputJson`); tools must be registered; ids must be unique slugs; inputs must be JSON objects; at most 12 steps.
   Anything else (including approval or timeout flags a model adds) is dropped. Invalid plans are rejected with reasons.
3. The valid result is a **draft** held on the server and shown for review. Nothing has run.
4. Nothing executes until you click **Start plan**, which re-validates through the controller and policy engine.
   Sensitive steps still stop at the approval gate.
5. One plan request at a time, one model call each, no automatic retry.

The planner prompt (updated in M4 and M5, **not yet re-tested against live Gemini**) now explains `{"$ref": ...}` step
references and tells the model to use `research.find_sources` -> `research.collect` -> `research.consolidate` for
multi-startup research, only to put literal URLs it was given into `browser.open`, and to list anything the tools cannot do
under "Not covered by the available tools". References in a model-written plan are validated (earlier steps only) before
the draft is shown.

API: `POST /api/plans`, `POST /api/plans/:planId/start`, `GET /api/llm/status`; run API: `POST /api/runs`,
`POST /api/runs/:id/{cancel,pause,resume}`, `POST /api/runs/:id/steps/:stepId/{approve,reject}`, `GET /api/run`,
`GET /api/tools`, `GET /api/health` (includes `browser: {launched, url}`).

## How the controller works (M2)

- Task states: `pending, running, waiting_for_approval, paused, completed, failed, cancelled, unverified`.
  Step states: `pending, running, waiting_for_approval, completed, failed, skipped, cancelled, unverified`.
- Steps run strictly in order; every state change is an SSE event carrying a snapshot.
- Policy is separate from the controller: unregistered tool => denied; sensitive tool or `requiresApproval` => approval.
- Reject => step `skipped`, rest `cancelled`. Cancel aborts the running step and starts nothing further.
- Pause takes effect before the next step. A failed step fails the task; later steps are explicitly `skipped`.
- A tool returning `verification: "unverified"` makes the task end `unverified`, never `completed`.

## M5 live checks (manual, 2026-10-28, Windows, installed Chrome, no Gemini calls)

The fixed 3-step plan (`research.find_sources` -> `research.collect` -> `research.consolidate`, query "AI startups",
10 startups requested) was run through the real server and a visible Chrome window **twice** (the second run after I
tightened source selection and the "many prices" rule):

| | Run 1 | Run 2 |
|--|-------|-------|
| Task result | `completed`, about 85 s | `completed` |
| Search | DuckDuckGo returned results; 7 were kept as "official-looking" (they were mostly startup-list / trend / newsletter sites, not startups) | 10 results all skipped as lists/directories, so **all 15 sources came from the labelled fallback seed list** |
| Records | 10 researched, 1 failed: `f6s.com` showed a **bot-check wall**, the step recorded it as failed ("not bypassed") and the next candidate replaced it | 10 researched, 0 failed |
| Fallback | 4 of the 10 records came from the seed list (labelled `fallback`) | 10 of 10 from the seed list (labelled) |
| Pricing | Mixed: some `found`, ElevenLabs `ambiguous` (promo) -> "Unavailable" | 3 `found` (Replicate, Hugging Face, Jasper), 6 `ambiguous` -> "Unavailable" (promos or 7+ price points), 1 `unavailable` |
| Name / product | Derived for all real startups (name from the page title, product from the meta description), each with evidence | Name 10/10, product 10/10 |
| Target market | Frequently "Unavailable" | 4/10 found, 6/10 "Unavailable" |

What this does and does not show: the mechanism works end to end on real sites (references, fallback labelling, URL
safety, per-site failure handling, consolidation). **The data quality is limited**: generic search queries return lists
and directories rather than startups, so discovery in practice relied on the seed list; pricing is deliberately
conservative (most startups end up "Unavailable"); `found` prices are literal strings on the page and were not checked
by hand against each plan (e.g. Replicate's `$0.00, $0.01` are tiny usage prices, not plan prices); target market is
found for fewer than half of the sites. The extracted values were not manually audited for correctness.

## M5.1 quality audit and extraction improvements (2026-10-28)

Full details, per-field classifications and quotes: `docs/audits/2026-10-28-m5.1-audit.md`. Raw record files are in `docs/audits/`.

- **Audit.** The 10 records of the second M5 live run (recovered from a helper-script copy; the first M5 run was not persisted
  and cannot be audited) were re-visited with the app's own browser tools; all 10 sites loaded and 8 had every stored quote still
  on the live page (Jasper's target-market quote and all of Synthesia's pricing quotes were not). Judged from quotes (not a
  full read of each page): Replicate's `found` pricing was **incorrect** (per-second hardware rates), Hugging Face's and Jasper's were
  **ambiguous**, Synthesia's and Cohere's target markets were **incorrect** (an FAQ question; a navigation label).
- **Pricing now ties a price to a plan name and billing period** only when the nearby text supports it. Promotional, crossed-out
  (two prices side by side), credit-grant, minimum-usage and usage-based figures are not plan prices. Same plan with two unlabelled prices
  is ambiguous. Result is `found` (clear plans listed, excluded ones named in `reason`/`ambiguousPlans`), `usage_based`, `ambiguous`, or
  Unavailable; raw prices and quotes are always kept.
- **Target market** uses explicit claims only (built/designed for X, helps/enables X, "for X" in meta/title/headings or lowercase in body). Menu labels,
  FAQ questions and customer testimonials do not count. If the home page has no claim, one same-site About / Solutions /
  Use-cases / Customers / Product page is read (`pages[].role = "about"`), never more than one.
- **Discovery.** A second, differently worded search ("<query> company official website pricing") runs only when the first search worked but gave
  fewer than 3 usable sites; a failed or blocked search is not retried. Directories seen in the audit (clutch.co etc.) are blocklisted.
  Seed-list entries stay labelled `origin: "fallback"`.
- **Persistence.** Finished runs are saved to `data/runs/<runId>.json` (git-ignored) so future results can be audited.
- Re-extraction of the same 10 sites with the new code (`docs/audits/m5.1-reextracted-original-sites.json`): 7 sites now have at least one plan-tied
  price (only Jasper complete, the rest partial), 6 have a target-market claim (Jasper and Synthesia only ambiguous), Replicate stays Unavailable. These new values were only spot-checked against quotes and are
  not a second full audit. A fresh pipeline run found 6 search-derived sources (openai.com, anthropic.com, crusoe.ai, fireworks.ai, typesafe.ai,
  clutch.co) and 4 labelled seed sources; the search-derived records were not hand-audited.
## Known limitations

- **Source discovery is weak.** Search results for generic queries are mostly lists/directories. Source selection is a
  heuristic (domain blocklist plus list/directory words in title or snippet) and takes the site root of each result; the
  curated seed list is what reliably supplies official startup sites. No LLM-assisted selection, no other search engine.
- **Step references are one-way and in-memory**: a step can read an earlier step's output via `{"$ref": "stepId.path"}`;
  outputs larger than 500,000 characters when resolved are refused. There are no loops/conditions in plans; repetition
  lives inside `research.collect`.
- **Research quality:** target market and product come from simple patterns/meta descriptions; pricing is reported only
  when unambiguous and may be "Unavailable" even if a human could read a price off the page. Name derivation requires the
  domain's brand word to appear in the page title.
- Extraction is pattern-based: it quotes prices but does not map them to plan names, may include promotional or
  struck-through prices (the live ElevenLabs page produced entries like "$6" next to "$1 per month"), caps at 12 prices,
  and depends on the page's rendered text. Product / target-market fields are not extracted (only meta description,
  headings and keyword quotes).
- Pricing hidden behind JavaScript interactions (toggles, tabs) or on a different page shows as "Unavailable" for the page that
  was read; `relatedLinks` suggests pricing pages but is not followed automatically.
- Search depends on DuckDuckGo's HTML endpoint and its markup; it may CAPTCHA or change. There is no fallback seed list
  yet, and no other search engine or paid search API.
- URL safety limits: DNS rebinding between check and use is not fully prevented (the browser resolves again); the request
  hook covers HTTP(S) requests but not WebSocket / WebRTC traffic from a page. Sites are not checked against robots.txt.
- Only one tab / one run at a time; run and draft state is in memory only.
- Pause cannot interrupt a step already running; cancelling a navigation cannot undo side effects a page already caused.
- No authentication on the local server; localhost use only.
